01結論

日常業務の自動化を主目的にするなら、引き続き freee。今回の確認で、MF にしかできないことは1点に減った。

内部統制（J-SOX）
子会社のプランに注意
freee の操作ログ（イベントログ）・自己承認の禁止・IP制限はエンタープライズだけ。子会社をアドバンスにする構成では、子会社にこれらがない。MF会計Plus は仕訳承認・操作ログ・SOC1 Type2 がある。
  • 推奨は freee（初版から変わらず）。MF に残る優位点（FBデータ作成の API）は月1回程度の業務で、画面操作で代わりがきく。対して MF会計Plus の制約（マスタ・証憑を API で作れない、仕訳を修正できない、人事・給与に公開 API がない）は日常業務に毎日効く。
  • 管理会計の3階層は、freee はアドバンスでも組める。部門の階層はアドバンス・エンタープライズとも5階層、セグメントは3つ。「事業＞部門＞支店」は子会社のアドバンスでもそのまま持てる。MF会計Plus は部門10階層だが、部門は画面でしか作れない。
  • 子会社を J-SOX の対象に含めるなら、freee のプラン構成を見直す。操作ログや自己承認の禁止が子会社でも必要なら、子会社もエンタープライズにするか、別の統制で補う必要がある。どの会社が評価範囲に入るかを先に確認する。
  • グループ5社は freee の上限ちょうど。freee の外部連携アプリ（プライベート）は5事業所まで。6社目ができると作り直しになるため、増える見込みがあるなら最初からパブリックアプリ（20事業所まで審査なし）で作る。アプリの種類は後から変えられない。
  • 費用は、経費精算を使う人数で結論が変わる。freee は経費精算・各種申請を使った人数に応じて従量課金がかかる。見積額を使った比較は社内資料にまとめた。

08確認事項

公式資料では分からず、回答によって判断が変わるものだけに絞った。初版の質問のうち、資料で答えが出たもの（freee の部門階層・総勘定元帳・支出管理の API）は外した。

freee への確認事項

1. 仕訳承認フローを有効にした事業所で、APIから仕訳を登録した場合、その仕訳も承認フローに乗りますか。
   それともAPI経由の登録は承認を経ずに確定しますか

2. エンタープライズのイベントログに、API/MCP経由の登録・更新・削除は残りますか。実行者（アプリ・ユーザー）を特定できますか。
   アドバンスの子会社で J-SOX の証跡を残す方法として推奨されるものはありますか

3. エンタープライズのIP制限をAPIにも適用する場合の運用方法を教えてください。
   リモートMCP（mcp.freee.co.jp）を利用する場合、接続元IPはどう扱われますか
