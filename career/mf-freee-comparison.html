社内独自システムとつなぎ、経理をどこまで自動化できるかという観点で両製品を整理したもの。 導入時に実現できる自動化の範囲と、外部システムからAPIで操作できる範囲の2軸で比較する。

調査方法。 MF は同社担当者からの個別回答を正とした。freee は公式の OpenAPI スキーマ（GitHub freee/freee-api-schema）から 会計99・人事労務68・請求書30の全エンドポイントを実際に読み、あわせて開発者サイトの解説ページ（アプリ種別・審査・権限・エラー・β版仕様・テスト環境・認可・事業所選択）を通読した。 freee の販売管理／申告／固定資産／IT管理／工数管理／業務委託管理のスキーマは未確認。

01結論

日常業務の自動化を主目的にするなら freee。MF会計Plus の API は「仕訳を投げ込んで試算表を読む」用途に絞られている。

給与計算の実行
API から給与計算処理そのものを起動する手段は両社ともない。ここは画面操作が残る。
  • 推奨は freee。MF 優位の2点は月に1回程度の業務で、画面操作で代替できる。対して MF の制約（マスタを API で作れない、人事・給与に外部 API がない）は日常業務に毎日効く。
  • 管理会計は部門階層で表現できる。「事業＞部門＞支店」の3階層は freee の部門階層（parent_id）でそのまま持てる。セグメント機能は不要。ただし部門階層はプラン依存。
  • グループ4社は4事業所になる。freee の「事業所」は帳簿の単位でほぼ法人単位。支店は部門として1事業所の中に収める。推奨の認可方式では1トークン＝1事業所のため、トークンは4本必要。

ざっくりした読み。 freee なら、日々の記帳からレポート取得までは一通り自動で回る。人が残るのは「給与計算の実行」「FBデータの作成と銀行送信」「決算整理と連結の判断」の3つ。
MF会計Plus は、仕訳の投入と試算表の取得は自動化できるが、その周辺が手作業として残る。科目・部門の追加、証憑の登録、入出金の突合、経費精算の承認、人事・給与の連携がいずれも画面操作になる。

03MF でしかできないこと

freee 優位の項目は多いので、逆側だけを挙げる。

項目内容
支払〜FBデータ作成のAPIMF は請求書受領システムとクラウド債務支払 API で、受領から FB データ作成まで対応できると回答。freee は支出管理／受取請求書で全銀協仕様の FB データを出力できるが、開発者サイトの API 一覧に支出管理・受取請求書の記載がない。会計 API に支払依頼はあるが FB データ生成の API は見当たらない月1回の業務であり、画面出力で代替可能
総勘定元帳の安定版APIMF は元帳の取得が可能と回答。freee は GET /api/1/reports/general_ledgers がβ版で、事前予告なく破壊的変更があり本番利用は非推奨仕訳データ（仕訳帳ダウンロード）は安定版で取得できるため、元帳を自前で組み立てる回避策はある
金融機関の自動連携数MF が約2,400、freee が約1,000。口座・カードの本数が多いほど効くAPI ではなく製品機能の差
連結会計は差になりません。freee も「freee連結会計」を2025年12月に提供開始しており、ほかに連結決算キット、結/YUI がある。 MF のクラウド連結会計より新しい製品であるため、実績面は個別に確認したほうがよい。

07freee への確認事項

仕様書に書かれておらず、回答によって判断が変わるものだけに絞った。

1. 部門階層について。
   ・何階層まで利用できますか。また、どのプランから利用できますか
   ・損益計算書(部門比較)APIで親部門のIDを指定した場合、配下の子部門の金額は合算されて返りますか
   ・部門別の損益を全支店分取得する際、5部門ずつの分割取得以外に推奨される方法はありますか

2. 仕訳承認フローを有効にした事業所で、APIから仕訳を登録した場合、その仕訳も承認フローに乗りますか。
   それともAPI経由の登録は承認を経ずに確定しますか

3. API/MCP経由の登録・更新・削除は監査ログに残り、実行者を特定できますか。
   J-SOX対応の証跡として監査法人に提示できる形式ですか

4. エンタープライズプランのIP制限をAPIにも適用する場合の運用方法を教えてください。
   MCPリモート版を利用する場合、接続元IPはどう扱われますか

5. 会計APIのレート上限について、/reports と証憑ダウンロード以外の具体的な数値上限を教えてください。
   月次で数万件規模の仕訳を投入する場合の推奨方式と、同規模の導入実績もお願いします

6. 総勘定元帳API（β版）の安定版への移行予定を教えてください。
   また安定版APIを廃止する場合の事前告知期間と旧仕様のサポート期限をお願いします

7. 無人バッチでの連携を想定しています。リフレッシュトークンの有効期限と、
   再認可（人の操作）が必要になる条件を教えてください

8. freee支出管理／受取請求書について。
   ・請求書の受領から支払、FBデータ（全銀協仕様）の作成までをAPIで実行できますか
   ・開発者サイトのAPI一覧に記載が見当たりませんでしたが、APIの提供予定はありますか

MF への確認事項

1. 公式API仕様書（会計Plus）に仕訳の更新系と総勘定元帳のエンドポイントが見当たりませんでした。
   仕訳修正と元帳取得を行う際のエンドポイント名を教えてください

2. 勘定科目・部門・プロジェクトの登録API、証憑の登録API、入出金明細の取得APIについて、
   提供予定と時期を教えてください

3. 会計PlusのMCP提供時期（2026年中を想定とのこと）の現時点の確度を教えてください

4. APIのレート制限・件数上限と、Webhookの有無を教えてください
